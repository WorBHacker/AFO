# Архитектура экосистемы (рабочее название: LocalChat)

Статус: черновик, решения на 2026-10-26. Код пишется только после того, как раздел «Открытые вопросы» закрыт для нужного этапа.

---

## 1. Цель и принципы

Не IDE, а **экосистема вокруг общего центра (хаба)**. Хаб постоянно знает проекты, связи между ними, запущенные процессы и вывод терминалов. Чат, VS Code и агенты — это клиенты хаба, которые видят один и тот же контекст. ИИ не нужно каждый раз объяснять, где лежит проект и что в нём происходит.

Принципы:

- **Видеокарта — для моделей, интерфейс — на процессоре.** Qt Widgets с программной отрисовкой. Без Chromium, WebEngine и QML.
- **VS Code остаётся редактором.** От IDE нужно только дерево папок, просмотр файлов и терминалы, остальное делает VS Code.
- **Гибрид моделей.** Локальные модели (одна видеокарта, одна модель за раз) + облачные API (параллельно, без ожидания видеокарты).
- **Модель выбирает человек.** Хаб даёт рекомендации с объяснением, но молча модель не меняет.
- **Действия с последствиями — только с подтверждением.** Секреты никогда не уходят в облако.
- **Журналы только дописываются.** История не переписывается.

## 3. Компоненты

```
                   ┌──────────────────────── Хаб ─────────────────────────┐
 Приложение ─────▶ │ Проекты и связи · дерево · git · процессы и порты    │ ◀── VS Code / Cline / Roo (MCP)
 (PySide6)         │ Терминалы (ConPTY, хаб — их владелец)                 │ ◀── внешние агенты (Claude Code и др.)
                   │ Инструменты (выполняются локально) · права доступа    │
                   │ Цикл агентов · журнал событий                         │
                   │ Шлюз моделей · рекомендации · учёт расходов           │
                   └──────────┬──────────────────────────┬────────────────┘
                              ▼                          ▼
                 llama-swap 127.0.0.1:8080        Anthropic · OpenAI · Gemini · OpenRouter/DeepSeek
                 (GPU: одна модель за раз)        (параллельно, по API-ключам)
```

- **Хаб** — фоновый процесс на Python. Агенты продолжают работать, когда окно закрыто.
- **Приложение** — нативное окно: проекты с деревом, просмотр файлов, чат, агенты, терминалы, статус модели и памяти.
- **Шлюз моделей** — общий каталог локальных и облачных моделей, адаптеры поставщиков, рекомендации, учёт денег.
- **Внешние агенты** — Claude Code, Codex CLI и т. п. запускаются в терминалах хаба, контекст получают через MCP.
- **VS Code** — редактор. Cline / Roo Code подключаются к хабу через MCP.

## 4. Принятые решения

**D1. Экосистема с хабом, своё IDE не делаем.**
VS Code — редактор. Своё — хаб, лёгкое приложение и агенты.

**D2. Хаб — отдельный процесс.**
Почему: агенты работают без открытого окна; у терминалов один владелец, а смотреть на них могут многие клиенты; внешние клиенты подключаются через MCP.

**D3. Интерфейс: Python + PySide6, Qt Quick (QML) с программным рендерером** (пересмотрено 2026-10-27, было: Qt Widgets).
Интерфейс рисует процессор: Qt Quick включается с программным графом сцены (`QSGRendererInterface.Software`, задаётся до первого окна), видеокарта остаётся моделям. WebEngine — это Chromium, его нет (PySide6-Essentials). Почему не C++: узкое место — модель, а не интерфейс.
Замер (2026-10-26): Electron-программы занимают ~90–110 МиБ видеопамяти каждая (VS Code ~91, Claude ~108, Chrome ~86), NVIDIA Overlay ~123 МиБ.
Замер (2026-10-27, окно 1280×820 на экране, собственная видеопамять процесса): Qt Widgets — 0 МиБ, **Qt Quick с программным рендерером — 0 МиБ (в том числе во время потокового ответа)**, Qt Quick на видеокарте (Direct3D 11) — 24 МиБ. Поверхность окна в DWM считается за самой Windows.
Почему ушли с Widgets: современный вид (свой заголовок окна, всплывающие панели, анимации, сворачивание) на Widgets пришлось бы рисовать вручную по элементу; в QML это встроено. Ограничение программного рендерера: нет шейдерных эффектов (размытие, настоящие тени) — тени рисуются слоями.

**D4. Как хаб видит, что происходит.**

| Источник | Что видно | Как |
|---|---|---|
| Терминалы, запущенные через хаб | весь вывод вживую, команда, код выхода | хаб создаёт их сам (ConPTY) |
| Любые процессы в папках проектов | команда, папка, порты, CPU и память — **без вывода** | psutil |
| Терминалы VS Code | вывод команд | позже: расширение VS Code (shell integration) пересылает в хаб |
| Файлы и git | дерево, изменения, ветка | наблюдение за файлами + git |

**D5. Локальные модели — через llama-swap.**
Один адрес `127.0.0.1:8080/v1`, модель выбирается полем `model`, при смене остальные выгружаются. Состав и замеры — в разделе 5.

**D6. Облачные поставщики:** Anthropic (Claude), OpenAI, Google Gemini, OpenRouter / DeepSeek и другие OpenAI-совместимые.

**D7. Адаптеры — по поставщику, а не одна OpenAI-совместимая прослойка.**

| Адаптер | Кого обслуживает |
|---|---|
| Anthropic — официальный SDK `anthropic` | Claude по API-ключу |
| OpenAI-совместимый | llama-swap (локальные), OpenAI, OpenRouter, DeepSeek и др. |
| Gemini | Google (позже) |

Внутри хаба — единый формат сообщений: текст, картинка, вызов инструмента, результат, размышления. Ответ поставщика **хранится как есть**, потому что некоторым поставщикам нужно возвращать собственные блоки без изменений (см. D14).

**D8. Claude Code по подписке — только через официальный CLI `claude`.**

- По документации Anthropic (Agent SDK, 2026-10): сторонним программам без отдельного разрешения запрещено встраивать собственный вход через claude.ai и пользоваться лимитами подписки. Поэтому хаб **не делает свой вход и не трогает токены подписки**.
- Хаб запускает CLI `claude`, уже залогиненный пользователем (так же работает расширение для VS Code):
  - интерактивно — `claude` в терминале хаба;
  - управляемо — `claude -p --output-format stream-json --verbose`; `--resume <session>` продолжает диалог; `--mcp-config` даёт инструменты хаба; `--permission-mode` / `--allowedTools` задают права; `--append-system-prompt` добавляет инструкции.
- Только для личного использования. Если экосистему будут использовать другие люди, им нужны свои API-ключи.
- У подписки свои лимиты использования, они учитываются отдельно от денег по API (D12).
- Заметка: `--bare` подписку **не использует**, ему нужен `ANTHROPIC_API_KEY`.

**D9. Инструменты выполняются локально в хабе — для любой модели.**
Модель только предлагает вызов, хаб выполняет его по правилам доступа. Managed Agents (облачная песочница не видит локальные файлы и терминалы) и облачный MCP-коннектор (нужен публичный адрес) как основу не используем.

**D10. Приватность.**
У каждого проекта флаг «можно отправлять в облако». Секреты (`.env`, ключи, файлы учётных данных) фильтруются всегда, в том числе в результатах инструментов.

**D11. Подбор моделей — гибкий, с рекомендациями.**

- На входе: тип задачи; нужные возможности (инструменты, картинки, контекст); флаг облака у проекта; состояние бюджета и лимитов подписки; что загружено на видеокарте и очередь к ней; **статистика самого хаба** (успешность, скорость и цена за задачу по моделям).
- На выходе: список вариантов с объяснением и оценкой цены и задержки.
- Правила задаёт пользователь: значения по умолчанию для ролей агентов и для проектов, жёсткие ограничения («проект X — только локально»), приоритет между качеством, ценой и скоростью.
- Молча модель не меняется. Автоматика — только если явно включена в профиле.

**D12. Бюджет — гибкий, с рекомендациями.**

- Уровни: общий → поставщик → проект → роль агента → задача. У каждого — мягкий порог (предупредить) и жёсткий (остановить или спросить), плюс период: день, неделя, месяц или задача.
- Учёт по каждому запросу: входные токены, токены из кэша, выходные × таблица цен (в настройках, с датой обновления). Лимиты подписки Claude Code учитываются отдельно. В `claude -p --output-format json` есть `total_cost_usd`, но это оценка на стороне клиента.
- Рекомендации: оценка цены до запуска по похожим задачам, прогноз на месяц, низкая доля попаданий в кэш, избыточная модель для простой задачи.

**D13. Ключи API — в диспетчере учётных данных Windows** (библиотека `keyring`). В файлах настроек ключей нет.

**D14. Журналы только дописываются.**
У новых моделей Claude блоки размышлений нужно передавать обратно без изменений, а правка ранних сообщений их ломает. Сжатие истории — средствами поставщика или новой сессией, но не переписыванием.

**D15. Особенности Claude API, которые учитывает адаптер** (по справке, кэш от 2026-10-06):

- С 2026-10-21 `temperature` / `top_p` / `top_k` вызывают ошибку 400 → адаптер их не отправляет. Глубина регулируется через `output_config.effort`.
- На новых моделях `tool_choice` `any` / `tool` вызывает ошибку 400 → только `auto` + `strict: true` в схеме инструмента.
- `stop_reason: "refusal"` → обработка: запасная модель или сообщение пользователю. Учитывать server-side `fallbacks`.
- Кэширование промпта: в начале — неизменная часть (системный промпт, инструменты, сводка проекта), переменная — после неё.
- Ориентир цен (за 1 млн токенов, вход/выход; чтение из кэша): Opus 5.5 — $4 / $20 (кэш $0.20); Sonnet 5.5 — $2 / $10 (кэш $0.20); Haiku 5.5 — $0.10 / $0.50; Fable 5.1 — $10 / $50. Цены проверять перед использованием.

**D16. Агенты двух видов.**

| | Свои агенты (цикл хаба) | Внешние агенты (Claude Code, Codex CLI…) |
|---|---|---|
| Модель | любая из шлюза: локальная или облачная | своя (Claude Code — по подписке, D8) |
| Инструменты | только инструменты хаба | свои встроенные + инструменты хаба через MCP |
| Права | полностью решает хаб | встроенные — флаги CLI; инструменты хаба — правила хаба (D18) |
| Видимость | каждый шаг | события `stream-json`, а в интерактивном режиме — терминал |

- **Профиль агента:** роль и инструкции, модель с запасной (рекомендации — D11), разрешённые инструменты, режим прав, доступные проекты, бюджет, лимит шагов и времени.
- **Прогон** (задача агента) — журнал, который только дописывается: вызовы модели, вызовы инструментов, подтверждения, расходы. Статусы: в очереди → работает → ждёт подтверждения → пауза → готово / ошибка / отменено. Прогон продолжается после подтверждения или перезапуска хаба. Пока один ждёт подтверждения, остальные работают.
- **Параллельность:** облачные прогоны идут одновременно, локальные стоят в очереди к видеокарте. Планировщик старается не гонять модели туда-обратно.

**D17. Права доступа — по типу действия. Режим по умолчанию «Спрашивать».**

| Тип | Примеры | По умолчанию |
|---|---|---|
| Чтение | файлы, поиск, git status/diff/log, процессы, вывод терминалов | без спроса, в пределах проекта, без секретов |
| Запись | создать или изменить файл | спросить, с показом diff |
| Команды | запуск в терминале | спросить. Команды из белого списка проекта — без спроса |
| Разрушительное | удаление, `git push`, `git reset --hard` | спрашивать всегда, белым списком не разрешается |
| Сеть | запросы, загрузки, установка пакетов | спрашивать каждый раз (D19) |
| Вне проекта или системное | другие папки, настройки Windows | запрещено |

- Режимы: «Только чтение», **«Спрашивать» (по умолчанию)**, «Песочница» (запись в git worktree без спроса, потом просмотр diff), «Доверенный» (белый список + запись в проекте).
- Окно подтверждений: очередь запросов, показ diff или текста команды; «разрешить один раз», «на весь прогон», «всегда для проекта» (создаёт правило), «отклонить с комментарием» (комментарий уходит агенту).
- Перед каждой записью сохраняется снимок файла, поэтому любое действие можно откатить. Полный журнал действий.
- Границы проекта проверяются по нормализованному пути, выйти за папку проекта через символические ссылки нельзя.

**D18. Подтверждения Claude Code — в ту же очередь.**
Claude Code запускается с `--permission-prompt-tool` → инструмент MCP хаба. Его запросы на разрешения появляются в общем окне подтверждений приложения.

**D19. Сеть: спрашивать каждый раз; веб-инструменты есть у всех моделей, в том числе у локальных.**

- Хаб даёт инструменты `web_search` и `web_fetch` (страница → текст) любой модели. У облачного Claude есть и свои серверные веб-инструменты, но для единых правил предпочтительны инструменты хаба.
- Каждый сетевой запрос — с подтверждением. Есть белый список доменов для быстрого разрешения (например, документация, pypi.org, npmjs.com).
- **Содержимое из сети — недоверенные данные.** Инструкции со страниц не выполняются. Агент, который читал сеть, не получает без подтверждения ни запись, ни команды.

**D20. Сначала одна задача — один агент.**
Несколько задач могут идти параллельно. Координатор, который делит задачу на подзадачи для других ролей, — на следующем этапе.

**D21. Уведомления о подтверждениях: Windows + Telegram-бот.**

- Windows: всплывающее уведомление и значок в трее, клик открывает окно подтверждений.
- Telegram-бот:
  - отвечает только твоему `chat_id`, кнопки «разрешить» / «отклонить»;
  - токен бота хранится в диспетчере учётных данных;
  - Telegram — облачный сервис, поэтому для проектов **без** флага облака (D10) отправляется только короткое уведомление без кода и diff;
  - разрушительные действия с телефона подтверждаются двумя шагами или не подтверждаются вовсе (Q14).

**D22. Контекст в пять слоёв: давать мало, но нужное. Подробности модель запрашивает инструментами.**

| Слой | Что в нём | Размер | Когда попадает к модели |
|---|---|---|---|
| L0. Карта экосистемы | все проекты (название, назначение одной строкой, стек, статус) + граф связей | ~0.5–2K токенов | всегда, в начале промпта (кэшируется) |
| L1. Карточка проекта | назначение, устройство, ключевые папки, как запускать / тестировать / собирать, соглашения, важные файлы, известные проблемы | ~1–3K на проект | для проекта в фокусе + краткие версии связанных |
| L2. Живое состояние | процессы и терминалы, последние ошибки, изменения git с прошлого сообщения, события | ~0.5–2K, только изменения | в конце промпта, на каждом шаге |
| L3. Подробности по запросу | чтение файлов, поиск, символы, diff, хвост терминала, информация о процессе | порциями | модель вызывает инструменты |
| L4. Память | короткие факты и решения по проектам и связям | ≤ 1K | связанные с проектами в фокусе |

- Порядок в промпте неизменный: L0 → L1 → диалог → L2. Неизменная часть стоит в начале ради кэша промпта.
- Бюджет для модели с контекстом 64K: L0 ≤ 2K; L1 ≤ 3K + по 1K на связанный проект; L4 ≤ 1K; L2 ≤ 2K. Результаты инструментов порциями: файл — 200–400 строк, терминал — последние 100 строк, поиск — 50 совпадений. **Для облачных моделей с контекстом 1M лимиты те же**, потому что каждый шаг агента стоит денег.
- **Инспектор контекста** в приложении показывает, что попало к модели, со счётчиком токенов. Блоки можно выключать, файлы — закреплять.

**D23. Карточки и заметки хранятся в хабе. В репозиторий — только экспорт по кнопке.**
Без спроса в проекте ничего не появляется. По кнопке хаб записывает `CLAUDE.md` / `AGENTS.md` / `.clinerules` для внешних агентов. Обычный путь для внешних агентов — MCP.

**D24. Карточки предлагает модель, подтверждаешь ты.**

- При добавлении проекта хаб собирает:
  - README и файлы зависимостей;
  - дерево папок на 2–3 уровня с учётом `.gitignore`;
  - существующие `CLAUDE.md` / `AGENTS.md` / `.clinerules`;
  - краткую историю git.

  Из этого модель составляет черновик, ты правишь и подтверждаешь.
- После значимых изменений (новые папки, изменились зависимости, много коммитов) хаб предлагает diff только к затронутым разделам.
- Если карточка ссылается на файл, которого уже нет, это место помечается как устаревшее.
- По умолчанию карточку пишет локальная модель. Облачная — только если у проекта разрешено облако (D10).

**D31. API для клиентов: REST + WebSocket.**

### 5.4 Известные проблемы

- Лимит памяти Windows почти исчерпан → увеличить файл подкачки (делает пользователь).
- Модели 27B на HDD загружаются ~3 минуты → перенести на NVMe.
- llama-swap пока запускается вручную или из сессии, автозапуска нет. Хаб запускает окно, а при входе в Windows — никто (Q8).
- Цены Claude зашиты в адаптер (`PRICES_ASOF`), обновляются вручную (Q9). Повышенная цена Haiku 5.5 для промптов длиннее 100K токенов не учитывается.
- У отменённого прогона Claude число выходных токенов — оценка (Anthropic сообщает его только в конце ответа).
- Бюджет проверяется по уже потраченному: оценки цены запроса до запуска нет (это этап 6, D12), поэтому один запрос может заметно перейти лимит. Лимиты подписки Claude Code — этап 4.
- Проекты: поиска по проекту пока нет — ripgrep не установлен, план: `git grep`, а `rg`, если появится. Если папку открытого проекта удалить или переименовать, наблюдение за ней молча прекращается до перезапуска хаба.

### Первые шаги кода (этап 0 → этап 1)

1. **Структура:**
   ```
   LocalChat/
     hub/      — сервер: api, db (миграции), gateway (адаптеры), events
     app/      — PySide6: окно, виджеты, рендер
     common/   — общие модели данных
     tests/
     data/     — база и файлы (в .gitignore)
   ```
2. **Скелет хаба:**
   - FastAPI на `127.0.0.1:8765`, одна копия, токены, проверка `Origin`;
   - `GET /v1/health`;
   - SQLite + механизм миграций; первая миграция — разговоры, сообщения, учёт расходов, модели, настройки;
   - WebSocket `/v1/events`.
3. **Шлюз, шаг 1:** адаптер llama-swap (потоковая логика из нынешнего `localchat/api.py`) и чат через хаб.
4. **Приложение, шаг 1:** окно чата поверх хаба (`render.py` переиспользуется). Если хаб не запущен, приложение запускает его само.
5. **Шлюз, шаг 2:** адаптер Anthropic + ключи + учёт расходов.

Судьба нынешнего кода `localchat/`:
- `config.py` и `store.py` заменяет база хаба;
- `api.py` делится на адаптер хаба и клиент в приложении;
- `render.py` переезжает в `app/` без изменений.

**Что за пользователем (не код):** увеличить файл подкачки (Q11); по желанию — перенести модели 27B на NVMe.
