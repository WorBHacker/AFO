## 2. Что показали исследования

**Движок.** stable-diffusion.cpp (MIT) — тот же ggml, что у llama.cpp, без PyTorch. Сборки для Windows в каждом
выпуске: `cpu` (сама выбирает AVX/AVX2/AVX-512), `vulkan` (30 МБ), `cuda12` (363 МБ + 563 МБ библиотек CUDA; Pascal и
новее, без Maxwell), `rocm` [о]. У каждого файла GitHub отдаёт sha256 (`digest`) — проверка AFO (D46) подходит как
есть. Выпуск — после каждого коммита, по нескольку в день, и **бывают поломки** (#1989, #1976) [п] → AFO ставит
**проверенную** сборку, а не самую новую.

**sd-server** [о]: OpenAI `POST /v1/images/generations` (синхронно, поле `model` не смотрит), A1111
`/sdapi/v1/txt2img|img2img`, свой асинхронный `/sdcpp/v1/img_gen` и `/sdcpp/v1/vid_gen` → `GET /sdcpp/v1/jobs/{id}`
(статус, шаг, превью) и `POST …/cancel`. Видео пишет сам (WebM/WebP/AVI) — ffmpeg для него не нужен. Адреса
`/health` нет. Нехватка памяти бывает тремя видами: выход с кодом 1, падение процесса (`0xC0000409`), и **пустая
серая картинка с «успехом»** на Vulkan (#1220) [п].

**llama-swap** (v270) [о]: сам направляет к модели `/v1/images/generations`, `/v1/images/edits`, `/sdapi/v1/txt2img`,
`img2img`; асинхронные `/sdcpp/v1/*` — только через `/upstream/<модель>/…` (грузит ли этот путь модель — проверить,
29.1). `checkEndpoint: /v1/models`. Правила подмены моделей переехали в `routing:`; верхние `groups` названы
«устаревшими» — **AFO их пишет сейчас** (`hub/llama_config.py`), проверить, читаются ли ещё (касается и моделей
чата).

**Картинки по железу** (подробно — §3): на процессоре — SDXS / SD-Turbo 512² за 1 шаг: 0,8–1,7 с на настольном
i7-12700 через OpenVINO [о FastSD], на ноутбуке в 3–6 раз дольше [оц]; та же Z-Image на процессоре через sd.cpp —
~6 мин на 512² [п]. Встроенная Arc 140V: SDXL 1024² за 7 шагов — 63–68 с [п]. NVIDIA 4 ГБ: Z-Image-Turbo с выносом в
ОЗУ — 2,17 с/шаг на 512² [о]. 6 ГБ (RTX 2070): Z-Image 512×1024, 10 шагов — 25 с [п].

**Видео по железу** (§3): NVIDIA 12 ГБ, Wan2.2 TI2V-5B Q8, 480×832×33 кадра — 139 с с `--offload-to-cpu` против
403 с с подбором по умолчанию [п #2118]; 8 ГБ + 32 ГБ ОЗУ — 111 с на 480²×33 кадра за 4 шага [п]; AMD через Vulkan —
30+ мин [п]; Iris Xe не проходит даже картинку [п #2073]. На слабой ОЗУ всё упирается в файл подкачки: 16 ГБ ОЗУ и
HDD — 5 ч на 5 с ролика, 32 ГБ и SSD — 20 мин [п].

**Облако** (цены на 2026-11-06) [о]: у OpenAI видео через API больше нет (Sora 2 закрыта 2026-09-24), картинки —
`gpt-image-2.x`, $0,006–0,21 за штуку. У Gemini API нет Veo и Imagen; картинки — Nano Banana ($0,034–0,134), видео —
`gemini-omni-1.2-flash` (~$0,35 за 5 с 720p, только платный тариф). **OpenRouter** — свои адреса картинок и видео, 63
и 33 модели, `usage.cost` в ответе, список цен через API: картинка от $0,009, видео 720p — от $0,03/с (Grok Imagine
Lite) до $0,10/с (Veo 3.1 Fast).

## 3. Совместимость: что получит каждый компьютер

Картинка — «по умолчанию» на этом уровне; модель меняется кнопкой «Быстрее ↔ Качественнее» (как в установке моделей,
10.6). Время — до замеров 29.1 ориентир, не обещание.

| Компьютер | Картинки | Видео | Что AFO делает особо |
|---|---|---|---|
| **Только процессор, 8 ГБ ОЗУ** | SDXS / SD-Turbo 512², 1 шаг; секунды–десятки секунд [о/оц] | облако | Файл подкачки выключен → совет (уже есть в мастере); старый процессор без AVX2/FMA → честное «здесь не пойдёт, только облако» |
| **Процессор, 16 ГБ** | + SDXL-Lightning 768², 2–4 шага (~10–12 с на настольном через OpenVINO [о]); Z-Image — только «медленно, минуты» | облако | Браузер + модель забивают 16 ГБ [п] → предупреждение о памяти |
| **Встроенная Intel Iris Xe / UHD** | как «процессор» или Vulkan с VAE по кускам; SD1.5-LCM / SD-Turbo 512² | облако | Vulkan здесь ненадёжен (#2073, #1031) → пробный запуск решает: видеоядро или процессор |
| **Intel Core Ultra (Arc 140V и т. п.)** | SDXL-Lightning 1024² с VAE по кускам, ~40 с [оц по п] | облако; «попробовать» — LTX-Video через OpenVINO (29.9) | 1024×768 вместо 1024², если VAE не помещается [п #1154] |
| **Встроенная AMD 680M/780M/890M** | Vulkan: SD-Turbo / LCM 512²; SDXL-Lightning ≤768² | облако | `GGML_VK_FORCE_MAX_ALLOCATION_SIZE` — иначе блок ≤2 ГБ [п]; 890M падает (#1340) → пробный запуск; только GGUF Q8_0, не fp8 (#1279) |
| **NVIDIA 2 ГБ** (MX, GT) | SD1.5-LCM / SDXS 512², кодировщик на процессоре [оц] | облако | Maxwell (MX110/130, 940MX, GTX 9xx) — нет в сборке CUDA → Vulkan |
| **NVIDIA 4 ГБ** (1050 Ti, 1650, 3050 4G) | Z-Image-Turbo Q3/Q4 с выносом в ОЗУ, 512–768², ~20–25 с [оц по о] | облако | Нужно 12–16 ГБ ОЗУ под вынесенные веса [оц]; «резервная видеопамять» NVIDIA тихо замедляет вместо ошибки → `--max-vram -1` |
| **NVIDIA 6 ГБ** (2060, 3050 6G, 3060 ноутбук) | Z-Image-Turbo Q4 / FLUX.2-klein-4B 1024², 4–8 шагов, ~25 с [п] | «попробовать медленно», если ОЗУ ≥ 32 ГБ: минуты на секунду ролика [п] | — |
| **NVIDIA 8 ГБ** (4060, 3070 ноутбук) | те же в Q6–Q8, 1024² | **локально**: Wan2.2 TI2V-5B за 4 шага, 2–3 с 480p, ~2 мин [п]; при ОЗУ < 32 ГБ — облако | Порог видео |
| **NVIDIA 12–16 ГБ** | Q8, все модели каталога | локально, 832×480, до 5 с; LTX-2.3 со своим ×2 | Как у этого компьютера (RTX 5080) |
| **AMD 4–8 ГБ** (RX 470/580/6600) | Vulkan: SD1.5-LCM 512² (~72 с за 20 шагов на RX 580 [п]); Z-Image Q4 512² — 7 с/шаг [п] | облако (Vulkan — 30+ мин [п]) | ROCm не предлагаем (Q19), Polaris его и не умеет |

Общие ловушки, которые AFO закрывает сама: файл подкачки (ОЗУ + подкачка = предел, веса в ОЗУ идут в него; `mmap` в
Windows его не экономит [оц]); модели на HDD (уже есть: самый быстрый диск, D49); драйвер NVIDIA старше нужного
для `cuda12` (минимум — 29.1) → Vulkan или совет обновить; маленький диск и медленный интернет (размер скачивания —
в карточке; для слабых — сборка Vulkan, 30 МБ, вместо CUDA, ~0,9 ГБ, если замер 29.1 покажет, что разница мала).

### 4.1 Движки

- **stable-diffusion.cpp `sd-server`** — один движок для картинок и видео на всех уровнях. Ставится, как llama.cpp
  (`hub/engines.py`): архив с GitHub, sha256 из `digest`, своя папка. Отличие — **закреплённая сборка**: в AFO записан
  проверенный тег (`master-NNNN-xxxxxxx`); новый тег берётся, только пройдя пробные картинки и видео на каждой сборке
  (`cpu`, `vulkan`, `cuda12`). Какую ставить: NVIDIA Pascal+ — `cuda12` или `vulkan` (по замеру 29.1), Maxwell, AMD,
  Intel — `vulkan`, без видеокарты — `cpu`. ROCm — нет (Q19).
- **Запуск — через llama-swap**, как модели чата: одна модель на видеокарте, подмена — его. Блок модели:
  `checkEndpoint: /v1/models`, `healthCheckTimeout` с запасом, флаги уровня (§4.2), у AMD — переменная окружения
  Vulkan.
- **Постобработка видео** — готовые программы без Python и CUDA, работают на любой видеокарте с Vulkan и на
  процессоре: `rife-ncnn-vulkan` (MIT; ветка TNTwise — модели RIFE до 4.25), `realesrgan-ncnn-vulkan` (MIT), ffmpeg
  (сборка gyan.dev essentials: GPL 3 — с AFO под GPL 3 совместима; у каждого файла `.sha256`). Всё — по требованию,
  только на компьютере, где есть локальное видео.
- **OpenVINO** — второй движок только для Intel без видеокарты или со встроенной графикой, и только если замер
  покажет, что sd.cpp там заметно медленнее или падает (29.9): там OpenVINO даёт картинку за 1–2 с на процессоре [о].

### 4.2 Уровень компьютера

1. **Что видно сразу** (`common/hardware.py`, без прав администратора): к нынешним реестру и NVML — выделенная и общая
   память через DXGI (у встроенной графики главное — общая), вычислительная способность NVIDIA (Maxwell → Vulkan),
   версия драйвера, есть ли `vulkan-1.dll`, AVX2 и FMA (`IsProcessorFeaturePresent`), ОЗУ, файл подкачки, тип диска.
2. **Пробный запуск**: `sd-server --list-devices` и картинка 256² за 1 шаг на самой маленькой модели — работает ли
   движок на этом устройстве и не вышла ли пустой.
3. **Замер**: та же картинка уровнем выше — секунд на шаг. Уровень = самая сильная модель, которая укладывается во
   время, приемлемое для этого уровня; итог хранится, как результаты замеров моделей чата (D49), и
   пересчитывается после обновления движка или драйвера.
4. Человек видит без терминов: «Картинки: да, ~20 с» · «Видео: в облаке — для видео здесь нужна видеокарта NVIDIA от
   8 ГБ». В мастере первого запуска нынешнее назначение «Картинки» (это зрение — модель смотрит на картинку)
   переименовывается в «Понимать картинки», рядом — «Рисовать».

### 4.3 Модели

- Каталог (`hub/model_catalog.json`): назначения `image` и `video`; у модели — несколько файлов (диффузия, текстовый
  кодировщик, VAE), установщик сейчас знает «модель + проектор» — расширяется до набора файлов.
- Ступени картинок: **лёгкая** — SDXS-512 (openrail++) или SD-Turbo (лицензия Stability: бесплатно до $1 млн выручки);
  **средняя** — SDXL-Lightning 2–4 шага; **основная** — Z-Image-Turbo (Apache 2.0, 8 шагов) и FLUX.2-klein-4B
  (Apache 2.0, 4 шага); **качество** — они же в Q8, FLUX.3 Image Klein (бесплатно для бизнеса до $5 млн — с
  пометкой). Видео: Wan2.2 TI2V-5B (Apache 2.0) и её 4-шаговые варианты; LTX-2.3 (бесплатно до $10 млн — пометка).
  HunyuanVideo 1.5 — нет: лицензия не действует в ЕС, Великобритании, Южной Корее, и нужно от 14 ГБ.
- **Расширение Q17**: GGUF диффузионных моделей их авторы почти не выпускают. Выбор Claude (можно поменять) —
  брать GGUF у названных в каталоге квантовщиков (тех, кого советует документация sd.cpp), лицензию — с карточки
  оригинала, sha256 — с Hugging Face, как сейчас. Иначе — скачивать оригинал и сжимать на месте (`sd-cli`), но это
  в 3–4 раза больше скачивания — плохо как раз для слабых.

### 4.4 Задание

- Таблица заданий в базе (миграция): что, какой моделью, где (здесь / облако), уровень, сид, статус, время, цена,
  файлы. Хаб говорит с sd-server асинхронным API (`/sdcpp/v1/img_gen`, `vid_gen` → опрос задания): ход и превью идут в
  окно событиями по WebSocket, «Стоп» → `cancel`.
- Видеокарта одна: локальное задание встаёт в ту же очередь, что прогоны агентов (D16); llama-swap выгружает модель
  чата. Пока идёт видео, модель чата ждёт — окно это показывает.

### 4.5 Лестница при сбое и проверка результата

- Сбой — это: код выхода не 0 (в том числе `0xC0000409`), оборванное соединение, в журнале движка `out of memory`,
  `ErrorOutOfDeviceMemory`, `failed to allocate`, и **результат-пустышка** — хаб сам смотрит картинку (почти один
  цвет, NaN) и не верит «успеху».
- Лестница (каждая ступень — новая попытка, сам, без вопроса): VAE по кускам → веса в ОЗУ (`--offload-to-cpu`,
  `--max-vram -1`) → веса с диска (`--params-backend …=disk`) → меньший размер → модель ступенью ниже → сборка `cpu`
  → карточка «здесь не получилось — в облаке ~$X?». Ступень, на которой вышло, запоминается для этой модели и этого
  компьютера: следующая картинка начинается с неё.
- Резко медленнее замера (вдвое и больше) на NVIDIA — признак «резервной видеопамяти» драйвера: совет в
  «Проверить систему», как выключить для `sd-server.exe`.

### 4.6 Видео в два шага

1. Основа: модель в своём разрешении и частоте (Wan — 832×480, 16 кадров/с; LTX — 640×360 и её ×2), 2–5 с; для
   видео — `--offload-to-cpu` (в 3 раза быстрее подбора по умолчанию [п]) и VAE по кускам во времени.
2. RIFE ×2 → 32 кадра/с (только ×2: на быстром движении больше — двоится [п]); Real-ESRGAN ×2 — только у моделей без
   своего увеличения и по желанию; ffmpeg собирает MP4 (H.264) — его откроет любой плеер и мессенджер.
- В окне: проверить, играет ли Qt Multimedia видео при программной отрисовке (D3); если нет — первый кадр в чате и
  «Открыть» системным плеером.

### 4.7 Облако

- Поставщики шлюза (`hub/gateway/`): **OpenRouter** — картинки и видео (асинхронно: задание → опрос → скачать),
  цены — из его списка вживую; **OpenAI** — только картинки; **Gemini** — картинки и `gemini-omni` (видео — только
  платный тариф). Ключи — те, что уже в «Подключениях».
- До отправки — оценка цены; карточка с причиной («для видео здесь мала видеопамять»); настройка «Облако для картинок
  и видео: спрашивать каждый раз (по умолчанию) / разрешено до $X в день»; бюджет D12; расход — из `usage.cost` или по
  таблице цен с датой (Q9, напоминание о ценах старше 60 дней). Картинка-образец уходит в облако только при флаге
  облака проекта (D10).
- Поставщики часто меняют модели (у OpenAI за полгода ушли Sora и три модели картинок) — список моделей не зашит,
  а берётся у поставщика; зашита только цена по умолчанию с датой.

### 4.8 Окно и инструменты

- «Нарисовать» и «Видео» в поле ввода чата: текст, форма (квадрат / широкая / высокая), «Быстрее ↔ Качественнее»,
  «По картинке» (приложенная к сообщению). Ход с превью и оценкой времени по замерам, «Стоп». Результат — в чате;
  «Ещё вариант» (новый сид), «Сохранить в проект» (запись файла — карточка D17), «Открыть папку». Файлы — в
  `data/media`, в PNG — запрос, модель, сид.
- Инструменты `generate_image` и `generate_video` для чата и агентов: локально — в очереди к видеокарте; облако — по
  правилам §4.7, у агента — подтверждением по классу «деньги».

## 6. Как проверять на сильном компьютере

Этот компьютер (RTX 5080, 16 ГБ) слабым не станет, поэтому: слабые карты — `--max-vram` (бюджет видеопамяти движка);
нет видеокарты — сборка `cpu`; AMD и Intel — сборка `vulkan` на NVIDIA (тот же путь кода, не те же драйверы);
железо в тестах — подставное (`common/hardware.py` с подменой), сбои — подставной sd-server (код выхода, обрыв,
серая картинка). Что не подменить — драйверы Intel и AMD, предел блока Vulkan, медленный диск — шаг 29.10.

## 7. Решения, которые ждут пользователя

Выбор Claude стоит первым; пока ответа нет — план идёт по нему (можно поменять):

1. **Облако** — спрашивать каждый раз с ценой; разрешение заранее с потолком — настройкой. (Идея говорила «тихо» —
   это против D10–D12.)
2. **GGUF от квантовщиков** (расширение Q17, §4.3) — да, названные в каталоге, лицензия с оригинала.
3. **OpenVINO** — только по замеру (29.9), не заранее: второй движок — вдвое больше того, что может сломаться.
4. **Модели с пределом выручки** (SD-Turbo, FLUX.3 Klein, LTX) — в каталоге с пометкой; по умолчанию — Apache 2.0
   (Z-Image, FLUX.2-klein-4B, Wan2.2) и SDXS.

## 8. Не делаем

- PyTorch, ComfyUI, Wan2GP, FramePack: гигабайты зависимостей, только NVIDIA, у Wan2GP лицензия запрещает встраивание в
  платный продукт.
- DirectML: в режиме поддержки, его заменяет Windows ML; Krita AI Diffusion уже отказалась.
- NPU Intel: только SD1.5-LCM 512², публичных замеров нет.
- Локальное видео на процессоре и старой встроенной графике: минуты–часы на секунду ролика.
