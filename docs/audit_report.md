## Как методика применена

`docs/Audit.md` — методика аудита IDE: пять доменов, отдельно AI-подсистема и Git, ещё шесть «упускаемых слоёв» и
взвешенная оценочная карта. LocalChat — не IDE: редактор — VS Code (D1). Поэтому каждый пункт методики сначала
проверен на применимость, а применимые — по коду `hub/`, `app/`, `vscode/` и `tests/`. Самые серьёзные находки
перепроверены вручную. Замеров не было: в проекте нет ни одного бенчмарка, и это само по себе находка (шаг 13.7).

пересчитаны. Оценки — от 1 до 5.

**Что уже сделано хорошо.**
- Хаб слушает только `127.0.0.1`. Запросы с заголовком `Origin` и чужим `Host` отклоняются, что защищает от DNS
  rebinding. Токены хранятся хэшем.
- Ключи лежат в диспетчере учётных данных Windows. Пароль подключений защищён scrypt.
- Подтверждения разделены по классам действий. В «Песочнице» модель работает в git worktree. Правки моделей
  сохраняются снимками по sha256, откат проверяет хэш файла.
- Контекст собирается слоями L0–L4 с бюджетами, код ищется через ripgrep и символы tree-sitter, а не чанками.
  Работает автоматический кэш Anthropic, история только дописывается (D14), запрос ужимается под окно модели.
- MCP работает в обе стороны. Локальные модели обслуживает llama-swap. TTFT, скорость и деньги считаются.
- Телеметрии нет. ripgrep, движки и модели скачиваются с проверкой sha256.

## Находки

### Безопасность (P0)

- **Классификатор разрушительных команд** — это regex по сырой строке (`hub/approvals.py:52-64`).
  - `git -C x push` и `git -c k=v push` не распознаются: regex ждёт подкоманду сразу за `git`.
  - Нет подкоманд `checkout -f`, `checkout .`, `switch -f`, `worktree remove --force`, `update-ref -d`,
    `reflog expire`, `gc --prune`, `filter-branch`.
  - PowerShell: не распознаются сокращения `-r`/`-rec` у `Remove-Item`, а также `Clear-Content`, `Format-Volume`,
    `diskpart`, `reg delete`.
  - Непрозрачные `-EncodedCommand` и `iex` проходят как обычные команды. В «Доверенном» всё это выполняется без
    вопроса.
- **`web_search` и ответ «для чата».** Такой ответ покрывает все следующие поиски: `grant_key` возвращает
  `"web_search"` (`approvals.py:115-128`). При этом D19 и docstring `chat.py:918` обещают «каждый раз».
- **D19 срабатывает не везде.** Правило «после чтения внешнего — запись с вопросом» не включается после
  `mail_read`, `http_request`, MCP-инструментов класса read и `screen_look`. Для Claude Code в «Доверенном» этой
  проверки нет вовсе (`mcp_server.py:301-302`).
- **«Доверенный» и проекты «только локально».** Модель читает файл такого проекта, затем без вопроса вызывает
  `web_fetch` или `web_search` и передаёт этот текст в адресе или запросе (`chat.py:907`, `chat.py:933`).
- **Папка данных хаба внутри проекта.** Если подключён проект LocalChat, `read_file("data/tokens/app.token")` не
  блокируется: `data/` лежит в checkout (`tools.py:263`, `secret_filter.py:20-26`). Секретность файла проверяется по
  сырому аргументу, а не по разрешённому пути — это обход через симлинк, хвостовые пробелы или `::$DATA`.
- **Пробелы фильтра секретов.**
  - Он не знает файлов `.npmrc`, `.docker/config.json`, `.kube/config`, `~/.ssh/*` и токенов `npm_`, `glpat-`,
    `sk_live_`, `tvly-`, `Authorization: Bearer`.
  - Журналы пишутся без фильтра (`common/logging_setup.py:39`). В них попадает текст бесед (`claude_code.py:458`,
    `mcp_client.py:263`, `chat.py:599`).
- **D10 и смена модели.**
  - При переходе от планировщика к исполнителю (`chat.py:534-543`) `_check_cloud` не вызывается. У запасной модели
    эта проверка есть (`chat.py:589`). Если планировщик локальный, а исполнитель облачный, результаты инструментов
    проекта «только локально» уйдут в облако.
  - `folder_read` и дерево элементов `screen_look` идут облачной модели без флага облака и без фильтра секретов
    (`chat.py:788-796`).
- **`http_request` и `web_fetch`.** Ключ подставляется по совпадению хоста без проверки схемы, поэтому может уйти по
  `http://` (`agent_tools.py:337-341`). `web_fetch` не блокирует 100.64.0.0/10 (CGNAT, Tailscale; `web.py:60-90`).
- **`run_python`.**
  - «Без сети» сделано подменой модуля `socket` (`agent_tools.py:42-50`) и обходится.
  - Дочерние процессы переживают таймаут, лимита памяти нет.
  - Главной защитой остаётся вопрос с кодом скрипта перед каждым запуском.
- **REST и WebSocket.** Любой токен читает сырые файлы, в том числе проектов «только локально»
  (`api/projects.py:109-114`), и получает все события вместе с текстом бесед (`events_ws.py:53`). Флаг «облачный
  клиент» соблюдается только в MCP (`mcp_server.py:95`).
- **Цепочка поставок.**
  - Если GitHub не дал `digest`, движки llama.cpp и llama-swap ставятся без sha256 (`engines.py:150`). ripgrep в
    таком случае отказывается ставиться (`ripgrep.py:66-67`).
  - У зависимостей только ограничения `>=`. Lock-файла и проверки на известные уязвимости нет.

### Git (P1)

- **Пути без `-z` и без `core.quotepath=false`** (`sandbox.py:87`, `judge.py:119`). Файл с кириллицей в имени
  ломает применение песочницы, судью и фильтр секретов.
- **Песочница.**
  - Переименование (R) превращается в «changed» с новым путём. Тогда `git show base:new` падает посреди
    применения, а часть файлов уже записана (`sandbox.py:89-109`).
  - Байты рабочего файла сравниваются с сырым blob (`sandbox.py:118-121`). При `core.autocrlf=true` это даёт
    конфликт на весь файл. Такая настройка стоит в системном gitconfig Git for Windows на этой машине.
  - Базой служит `HEAD` worktree, поэтому коммит модели в песочнице прячет её изменения (`sandbox.py:104`).
  - Worktree и ветка не убираются ни при удалении чата, ни после сбоя (`api/conversations.py:175-182`).
  - Если `ensure` сбоит, чат молча получает настоящий проект (`chat.py:1287-1291`).
  - Окно показывает первые 400 строк diff и не говорит, что есть ещё.
- **Блокировки.** `GIT_OPTIONAL_LOCKS=0` и `GIT_TERMINAL_PROMPT=0` выставлены только в `projects.git`
  (`projects.py:159`); у песочницы, судьи и полигона их нет. Ошибки `index.lock` не обрабатываются.
- **Полигон.** Коммит идёт с хуками и подписью пользователя, ошибки проглатываются (`proving.py:110-119`).
  Глобальный `commit.gpgsign` или `core.hooksPath` тихо ломает прогон.
- **Git-инструменты моделей.**
  - `git_diff` не видит индекс и не умеет показать diff ветки против `main`.
  - `git_log` есть только в MCP (`mcp_server.py:212-223`).
  - Фильтр секретов в `git_diff` режет пути с пробелами (`tools.py:385`).
- **Точки отсчёта судьи** — деревья, на которые ничего не ссылается, поэтому `git gc` может их удалить
  (`judge.py:100-110`). Чинится в шаге 11.6.

### Защита данных и кодировки (P1)

- **Запись файлов.**
  - Запись неатомарная (`changes.py:179`, `agent_tools.py:279-286`).
  - `write_file` теряет BOM.
  - `edit_file` с найденным однострочным `old_text` вставляет `\n` в CRLF-файл, и концы строк смешиваются
    (`changes.py:149-150`).
- **Перезапись чужих правок.** `write_file` перезаписывает файл, даже если пользователь поменял его после того, как
  модель его прочла: хаб не помнит, какую версию видела модель (`tools.py:260-283`).
- **Просмотрщик.** BOM не снимается, UTF-16 считается бинарным, тип концов строк не показан
  (`projects.py:235-254`).
- **Невидимые и bidi-символы** (Trojan Source) нигде не помечаются. В том числе в diff на карточке подтверждения,
  где человек решает.
- **Восстановление.**
  - Перед миграциями копия базы не делается, команды восстановления нет (`server.py:103`, `backup.py`).
  - У хаба нет `faulthandler`, поэтому сбой tree-sitter не оставит следа. У окна он есть (`app/__main__.py:52-56`).
  - Черновик сообщения один на все чаты и не переживает сбой (`Composer.qml:13`).

### Производительность и терминалы (P1–P2)

- **Длинные чаты.** Открытие чата рендерит Markdown и pygments всех сообщений в потоке окна, история приходит без
  пагинации (`controller.py:1102`, `rows.py:461-472`, `api/conversations.py:78`).
- **Наблюдатель.**
  - Окно 0,4 с отсчитывается от первого события, а не от последнего (`watch.py:65`, `watch.py:278-294`).
  - На пачку событий запускается около 6 процессов git, `rev-parse` повторяется (`projects.py:182`, `:262`, `:295`).
  - `cards._tree` вызывает `ls-files --others` на каждую папку (`cards.py:84-95`).
- **Индекс символов** молча неполон после обрезки до 20 000 файлов: флаг `complete` не сбрасывается
  (`symbols.py:213`).
- **Терминалы и команды.**
  - `run_command` с вопросом `[y/N]` висит до таймаута 120 с (`commands.py:79-102`).
  - После переполнения очереди событий (код 1013) окно не дозапрашивает пропущенный вывод терминала
    (`app/ui/terminals.py:408-417`).
  - pyte разбирает вывод всех терминалов проекта, даже скрытых.

## Что LocalChat не делает (D1)

Эти пункты методики сознательно не входят в программу:
- **Редактор и отладка** — VS Code: LSP, DAP и отладка, составной запуск и hot reload, мультикурсор, структурный
  поиск и замена, частота кадров 120–240 Гц.
- **Отдельные инструменты** — клиенты БД, HTTP и hex.
- **Git-клиент** — VS Code: редактор слияния, стейджинг по строкам, blame, интерактивный rebase. Подпись коммитов и
  хранилище учётных данных Git тоже не нужны: хаб не коммитит и не пушит в проекты пользователя.
- **Удалённая разработка** — WSL, SSH, контейнеры: пока только Windows (Q19).
- **Маркетплейс расширений** — его роль играет MCP.

Теневые точки сохранения цели — шаг 11.6. Local History через наблюдатель — кандидат на потом, после шага 13.5. Это
снимки всех изменений файлов проекта, включая правки Claude Code и команд.

## Дополнение: редактор кода (D47, этап 14)

2026-11-02, после аудита, пользователь решил добавить в окно базовый редактор кода с подсказками и ИИ-дописыванием в
духе Copilot. Делается он после этапа 13. С ним становятся применимыми пункты методики, которые выше помечены
«не применимо»:
- **Буфер и кодировки.**
  - Правка с сохранением кодировки, BOM и концов строк.
  - Отмена одной операцией для «Заменить все» и для правки моделью.
  - Задержка ввода и подсветка на файле в 1 МБ меряются стендом 13.7.
- **Hot exit.** Черновики несохранённого восстанавливаются после сбоя окна.
- **Внешние изменения файла.** Полоса «файл изменился на диске» с выбором вместо молчаливой перезаписи. Сохранение
  проверяет sha256 исходной версии.
- **Local History.** Сохранения из редактора получают снимки и откат, как правки моделей.
- **Сетевая прозрачность FIM.** Код для дописывания уходит только модели роли, которую выбрал человек. В облако —
  только из проектов с облаком и после фильтра секретов.

Не применимыми остаются: LSP и DAP (подсказки и переход к определению работают по индексу символов хаба), мультикурсор,
структурная замена, 120–240 Гц, Git-клиент.

## Замеры, шаг 13.7

2026-11-03 появился стенд `tests/stress/` (`pytest -m stress`, в обычный прогон не входит): синтетические данные, без
сети и моделей. Цифры до и после оптимизаций и что по ним сделано — в `ARCHITECTURE.md`, §5.3, запись этапа 13.7.
Главное:
- старт хаба 2,6 → 1,07 с: SDK Anthropic загружается при первом обращении к Claude, а не при старте;
- открытие чата из 1000 сообщений держало поток окна 0,7 с, теперь 25 мс: строки делаются в фоне;
- 200 000 строк в терминале: окно 8,9 → 1,6 с, хаб тратит вдвое меньше процессора;
- 5000 изменений файлов за 2 с: 3 пачки и 12 процессов git вместо 10 и 60;
- историю чата частями по цифрам делать не нужно: хаб отдаёт 1000 сообщений за 7 мс.

Оценка домена «Ядро и производительность» — **4** вместо «3 (без замеров)»: цель этапа достигнута. Что держит её ниже
пяти: смена темы в длинном чате (0,66 с в потоке окна) и pyte на широких символах.
